# React 점진적 화면 만들기 실습 가이드

2026-11-13

## 개요

수강생이 "음료 자판기" 미니 쇼핑몰의 메인 화면을 7단계에 걸쳐 직접 키워 가며 React의 핵심 개념을 익히는 실습입니다. 각 단계는 앞 단계 코드에 기능 하나만 더하고, 브라우저에서 결과를 확인한 뒤 다음으로 넘어갑니다.

**완성 화면:** 헤더(로고, 검색창, 장바구니, 카테고리 메뉴), 홈(배너, 추천·인기·신상품), 검색 결과(결과 내 재검색, 정렬, 페이지 이동), 푸터. 상품 데이터는 FastAPI 백엔드와 MariaDB에서 받아옵니다.

**대상:** HTML, CSS, JavaScript 기초(배열 `map`, 화살표 함수, `fetch`)를 알고 React는 처음이거나 막 시작한 수강생.

**진행 원칙**

- **한 단계에 새 개념은 1~2개만** 넣습니다. 개념이 겹치면 어디서 막혔는지 찾기 어렵습니다.
- **먼저 동작하게 만들고, 그다음 나눕니다.** 한 파일에서 동작을 확인한 뒤 컴포넌트로 분리합니다.
- **단계마다 "완성 코드 스냅샷"을 둡니다.** 뒤처진 수강생도 다음 단계 시작 코드를 받아 바로 합류할 수 있습니다.
- **왜 이렇게 바꾸는지 먼저 보여 줍니다.** 예를 들어 새로고침하면 검색 조건이 사라지는 문제를 직접 겪게 한 뒤 URL 동기화를 소개합니다.

## 사전 준비

수업 전에 모든 수강생 PC에서 프론트엔드와 백엔드가 둘 다 뜨는지 확인해야 합니다. 4단계부터는 백엔드가 꺼져 있으면 화면에 502 에러만 나옵니다.

**개발 환경**

| 항목 | 내용 |
| --- | --- |
| 프론트엔드 | Node.js, Vite + React (`frontend` 폴더) |
| 백엔드 | Python 가상환경(`.venv`), FastAPI + uvicorn (`backend` 폴더) |
| DB | MariaDB, 테스트 DB `test_vmshop` |
| 편집기 | VS Code + ESLint 확장 |

**테스트 DB 만들기** (처음 한 번)

1. `backend/sql/01_test_schema.sql` 실행: 테이블 생성 (users, categories, products, orders, order_items)
2. `backend/sql/02_test_seed.sql` 실행: 상품 35개, 카테고리 7개, 주문 16건

**실행 (터미널 2개)**

```powershell
# 터미널 1 : 백엔드 (8001 포트, 테스트 DB)
cd backend
$env:DB_NAME='test_vmshop'; .\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8001 --reload

# 터미널 2 : 프론트엔드 (5173 포트)
cd frontend
npm run dev
```

실습 중에는 백엔드에 `--reload`를 붙여 코드를 고치면 서버가 자동으로 다시 시작되게 합니다. 확인: `http://localhost:8001/docs`와 `http://localhost:5173/test.html`이 모두 열려야 합니다.

**요청 흐름: 화면의 상품 데이터는 Vite 프록시를 거쳐 백엔드에서 온다**

```
                fetch                    HTTP                    SQL
┌──────────────┐     ┌──────────────────┐     ┌───────────────────┐     ┌──────────────────────┐
│   브라우저    │ ──▶ │  Vite 개발 서버   │ ──▶ │      FastAPI      │ ──▶ │       MariaDB        │
│ localhost:5173│     │ /search 요청을    │  ┆  │   uvicorn :8001   │     │     test_vmshop      │
│   test.html   │     │ 8001로 전달(프록시)│  ┆  │ app/product01.py  │     │ categories, products │
└──────────────┘     └──────────────────┘  ┆  └───────────────────┘     └──────────────────────┘
                                            ┆
                              8001이 꺼져 있으면 여기서 502
```

브라우저는 항상 5173으로만 요청하고, Vite가 `/search` 요청을 8001 백엔드로 넘깁니다. 그래서 백엔드가 꺼져 있으면 화면에는 502가 나옵니다.

**단계별 스냅샷 준비**

- 강사용 저장소를 git으로 관리하고 단계가 끝날 때마다 태그를 달아 둡니다 (`step-1` ~ `step-7`). 현재 프로젝트는 git 저장소가 아니므로 `git init`부터 합니다.
- git을 아직 배우지 않은 반이라면 단계별 폴더를 zip으로 나눠 배포합니다.
- `test.html` 같은 **별도 진입점**을 쓰면 기존 화면(`index.html`)을 남겨 두고 새 화면을 나란히 만들 수 있습니다. 이전 단계와 비교하며 설명하기 좋습니다.
- 파일명 뒤에 `_01`, `00`을 붙여 버전을 관리하면 어느 파일이 최신인지 헷갈립니다. 수강생에게도 스냅샷은 git이나 폴더로만 나누게 안내합니다.

## 전체 로드맵

7단계, 약 11시간입니다. 하루 3~4시간 수업이면 3~4일에 맞습니다. 1~3단계는 프론트엔드만으로 진행하고, 백엔드는 4단계부터 필요합니다.

| 단계 | 주제 | 화면에서 달라지는 것 | 핵심 개념 | 시간 |
| --- | --- | --- | --- | --- |
| 1 | 상품 카드 목록 | 배열 데이터로 카드 4개 표시 | JSX, 컴포넌트, props, `map`과 `key` | 60분 |
| 2 | 레이아웃 나누기 | 헤더, 바디, 푸터 구조 | 컴포넌트 분리와 조립, 시맨틱 태그, CSS 접두사 | 60분 |
| 3 | 장바구니 담기 | 담기 버튼, 개수 표시, 알림(토스트) | `useState`, 이벤트, 상태 끌어올리기, `useEffect` 정리 함수 | 90분 |
| 4 | 백엔드 데이터 연결 | 홈의 추천·인기·신상품 섹션 | Vite 프록시, `fetch`, 로딩·에러 상태, 커스텀 훅 | 120분 |
| 5 | 검색 화면 | 1차·2차 검색, 정렬, 페이지 이동 | 제어 컴포넌트, 조건부 렌더링, 작은 컴포넌트 재사용 | 120분 |
| 6 | 주소와 화면 동기화 | 새로고침·뒤로 가기 유지 | URL 쿼리, `history.pushState`, `popstate` | 90분 |
| 7 | 카테고리 (풀스택) | 카테고리 메뉴, 칩, 카드 표시 | DB 변경이 API와 화면까지 이어지는 흐름 | 120분 |

시간에는 강사 시연과 수강생 실습, 확인이 모두 들어갑니다. 시간이 모자라면 6단계를 강사 시연으로 대신하고, 7단계는 과제로 돌릴 수 있습니다.

## 단계별 실습 상세

각 단계는 목표, 실습 순서, 확인 포인트, 자주 하는 실수 순서로 진행합니다. 확인 포인트를 모두 통과한 수강생만 다음 단계로 넘어갑니다.

### 1단계. 상품 카드 목록 (60분)

**목표:** 배열 데이터를 컴포넌트로 반복해 화면에 그린다.

1. `App.jsx`에 상품 배열(`id`, `name`, `price`, `stock`, `image_url`)을 만든다.
2. 카드 하나를 `App.jsx` 안에 JSX로 직접 그린다.
3. 카드를 `components/ProductCard.jsx`로 옮기고 `product`를 props로 받는다.
4. `products.map()`으로 카드를 여러 개 그리고 `key={product.id}`를 넣는다.
5. `stock === 0`이면 "품절"을 표시한다 (조건부 렌더링 맛보기).

**확인 포인트**

- 카드 4개가 보이고, 사이다는 "품절"로 표시된다.
- 브라우저 콘솔에 `key` 경고가 없다.

**자주 하는 실수:** 이미지를 `src/assets`가 아니라 `public/images`에 두고 `/images/cola.svg`로 부르는 이유를 헷갈립니다. `public` 폴더는 사이트 주소의 `/`가 된다는 점을 먼저 설명합니다.

### 2단계. 레이아웃 나누기 (60분)

**목표:** 화면을 헤더, 바디, 푸터 컴포넌트로 나누고 최상위 컴포넌트는 조립만 하게 한다.

1. 종이에 완성 화면을 그리고 박스를 쳐 컴포넌트 이름을 붙인다 (5분 활동).
2. `Header`, `Footer`, `ProductGrid`를 만들고 `<header>`, `<main>`, `<footer>` 태그를 쓴다.
3. 최상위 컴포넌트에는 세 컴포넌트를 배치하는 코드만 남긴다.
4. CSS 클래스에 접두사(예: `t-`)를 붙여 기존 스타일과 섞이지 않게 한다.
5. 색상은 `:root`의 CSS 변수로 모아 한 곳에서 바꾼다.

**확인 포인트:** 최상위 컴포넌트가 20줄 안팎이고, 헤더의 로고 문구를 바꾸려면 `Header` 파일 하나만 열면 된다.

**자주 하는 실수:** `export default`와 `import` 이름이 다르거나 경로에서 `./components/`를 빠뜨립니다. 화면이 하얗게 나오면 콘솔부터 보게 합니다.

### 3단계. 장바구니 담기 (90분)

**목표:** 카드의 버튼을 누르면 헤더의 장바구니 개수가 늘어난다.

1. 먼저 `ProductCard` 안에 `useState`로 개수를 두고 버튼을 눌러 본다. 카드마다 숫자가 따로 늘어나고 헤더는 모른다는 문제를 직접 본다.
2. 상태를 공통 부모(최상위)로 옮기고 `cartCount`는 헤더에, `onAddCart` 함수는 카드에 props로 내려준다 (상태 끌어올리기).
3. 품절 상품은 버튼을 `disabled`로 만든다.
4. 담으면 "'콜라'를 담았습니다" 알림을 띄우고, `useEffect` + `setTimeout`으로 2초 뒤 지운다.
5. `useEffect`가 돌려주는 정리 함수에서 `clearTimeout`을 부른다. 빠르게 연달아 눌러 보며 왜 필요한지 확인한다.

**확인 포인트**

- 어느 카드에서 담아도 헤더 숫자가 하나씩 늘어난다.
- 알림을 연달아 띄워도 마지막 알림이 온전히 2초 보인다.

**자주 하는 실수:** `onClick={onAddCart(product)}`처럼 함수를 바로 호출해 에러가 나거나 무한 렌더링이 생깁니다. `onClick={() => onAddCart(product)}`와 비교해 보여 줍니다.

### 4단계. 백엔드 데이터 연결 (120분)

**목표:** 하드코딩한 배열 대신 API에서 받은 상품으로 홈 화면을 채운다.

1. 브라우저에서 `http://localhost:8001/docs`를 열고 `GET /search/products?sort=popular`을 직접 호출해 응답 모양(`total`, `items`)을 먼저 본다.
2. `vite.config.js`에 `/search` 프록시를 설정한다. 같은 주소로 요청하므로 CORS 설정이 필요 없다는 점을 설명한다.
3. API 호출은 `testProductApi.js` 한 곳에 모은다. `res.ok`가 아니면 `HTTP 상태코드`를 담아 에러를 던진다.
4. 컴포넌트 안에서 `useEffect` + `fetch`로 한 번 만든 뒤, 불러오는 중·에러·결과 세 가지 화면을 모두 표시한다.
5. 추천·인기·신상품 섹션이 같은 코드를 세 번 반복하는 것을 보여 주고, 커스텀 훅 `useProductSearch(params)`로 묶는다.
6. 응답이 오기 전에 조건이 바뀌면 늦게 온 응답을 버리도록 `ignore` 플래그를 넣는다.

**확인 포인트**

- 홈에 섹션 3개가 4개씩 나오고, 백엔드를 끄면 "상품 검색 실패 (HTTP 502)"가 나온다.
- 개발자 도구 Network 탭에서 요청 3개와 각 응답을 찾을 수 있다.

**자주 하는 실수:** `useEffect`의 의존성 배열에 객체를 그대로 넣어 요청이 끝없이 반복됩니다. 객체는 렌더링마다 새로 만들어지므로 `JSON.stringify(params)`로 문자열 키를 만들어 비교하는 방법을 보여 줍니다.

### 5단계. 검색 화면 (120분)

**목표:** 상품명 검색, 결과 내 재검색, 정렬, 페이지 이동이 되는 검색 결과 화면을 만든다.

1. 검색창 `SearchBar`를 제어 컴포넌트(`value` + `onChange`)로 만들고, `<form onSubmit>`에서 `preventDefault()`를 부른다.
2. 같은 `SearchBar`를 헤더(1차 검색)와 결과 화면(2차 검색)에서 props만 바꿔 재사용한다.
3. 화면 상태 `view`(home/search)를 두고 조건부 렌더링으로 홈과 검색 결과를 바꾼다.
4. 정렬 옵션을 `GET /search/sort-options`에서 받고, 실패하면 기본 목록을 쓴다.
5. 페이지 번호 컴포넌트를 만들고, 검색어나 정렬이 바뀌면 1페이지로 돌아가게 한다.
6. 검색어 칩(×)과 "검색 결과가 없습니다" 안내를 넣는다.

**확인 포인트**

- "주스" → 결과 내 재검색 "오렌지" → 2개.
- "%" 하나만 검색해도 전체 상품이 나오지 않고 "100% 오렌지주스"만 나온다.
- 다음 페이지로 넘기고 정렬을 바꾸면 1페이지로 돌아간다.

**자주 하는 실수:** 헤더에서 새 검색어로 바꿔도 검색창에 예전 글자가 남습니다. `useState(initialValue)`는 처음 한 번만 읽히기 때문입니다. `key={keyword}`를 주어 컴포넌트를 새로 만드는 방법을 소개합니다.

### 6단계. 주소와 화면 동기화 (90분)

**목표:** 새로고침하거나 뒤로 가기를 눌러도 같은 검색 화면이 나온다.

1. 5단계 화면에서 검색 후 새로고침을 눌러 조건이 사라지는 문제를 먼저 겪는다.
2. 주소창 → 화면 상태 `readUrl()`, 화면 상태 → 주소창 `toUrl()` 두 함수를 만든다 (`URLSearchParams`).
3. 화면을 바꾸는 곳을 `navigate()` 하나로 모으고, 그 안에서 `history.pushState()`와 `setRoute()`를 함께 부른다.
4. `popstate` 이벤트를 듣고 뒤로·앞으로 가기 때 주소를 다시 읽는다. 정리 함수에서 리스너를 제거한다.
5. 기본값(추천순, 1페이지)은 주소에 넣지 않아 주소를 짧게 유지한다.

**확인 포인트:** `/test.html?view=search&q=주스&sort=popular&page=2`를 새 탭에 붙여 넣으면 같은 화면이 나오고, 뒤로 가기로 홈까지 돌아갈 수 있다.

**자주 하는 실수:** `pushState`만 부르고 `setRoute`를 빠뜨려 주소는 바뀌었는데 화면은 그대로입니다. `pushState`는 React에 알리지 않는다는 점을 강조합니다. 이 단계를 마친 뒤 React Router가 같은 일을 대신해 준다고 연결해 주면 좋습니다.

### 7단계. 카테고리 풀스택 연동 (120분)

**목표:** DB에 카테고리를 추가하고, API와 화면까지 끝까지 반영한다. 기능 하나가 DB → API → 화면으로 이어지는 흐름을 직접 겪는 것이 핵심입니다.

1. **DB:** `categories` 테이블을 만들고 `products.category_id`와 외래키를 추가한다. 카테고리 7개를 넣고 상품과 연결한다. 탄산수를 "물"과 "탄산" 중 어디에 둘지 토론하면 분류 기준을 생각해 볼 수 있다.
2. **SQL 파일:** 스키마와 시드 파일에도 같은 내용을 넣는다. 다시 만들어도 같은 DB가 나오게 하기 위해서다.
3. **API:** `GET /search/categories`를 추가하고, `/search/products`에 `category_id` 필터와 `category_name`을 추가한다. `/docs`에서 먼저 확인한다.
4. **화면:** 헤더의 하드코딩된 바로가기 검색어를 API로 받은 카테고리 메뉴로 바꾼다. 주소에 `cat`을 추가하고, 결과 제목 · 칩 · 카드에 카테고리 이름을 표시한다.

**확인 포인트**

- 메뉴에 "탄산 7"이 보이고, 누르면 탄산수 2개를 포함해 7개가 나온다. 판매중지 상품은 나오지 않는다.
- "주스" 카테고리에서 결과 내 재검색 "오렌지" → 2개.
- 카테고리가 없는 상품(35번)도 전체 검색에서 빠지지 않는다.

**자주 하는 실수:** 카테고리 이름을 붙이려고 `JOIN`을 쓰면 카테고리가 없는 상품이 결과에서 사라집니다. `LEFT JOIN`과 비교해 35번 상품으로 확인시킵니다.

## 강의 운영 팁

한 단계는 "시연 → 따라 하기 → 혼자 변형 → 확인" 네 부분으로 운영하면 수준 차이가 있는 반에서도 속도를 맞추기 쉽습니다.

| 순서 | 비중 | 하는 일 |
| --- | --- | --- |
| 시연 | 20% | 강사가 라이브 코딩. 일부러 실수를 하고 콘솔 에러를 읽는 법을 보여 준다. |
| 따라 하기 | 40% | 수강생이 같은 코드를 입력한다. 복사·붙여넣기보다 직접 입력을 권한다. |
| 혼자 변형 | 30% | 비슷한 기능을 힌트만 보고 만든다 (아래 과제 예시). |
| 확인 | 10% | 확인 포인트를 서로 점검하고, 다음 단계 스냅샷을 배포한다. |

**단계별 혼자 변형 과제 예시**

1. 카드에 "NEW" 배지 추가 (등록 14일 이내)
2. 푸터에 고객센터 영역을 따로 컴포넌트로 만들기
3. 장바구니에 "상품별 수량"을 저장하기 (개수 대신 배열 상태)
4. 홈에 "낮은 가격순" 섹션 추가 (섹션 배열에 한 줄)
5. 한 페이지 상품 수(12/24) 선택 기능
6. 한 페이지 상품 수도 주소에 담기 (`size`)
7. 카테고리를 하나 더 만들고(예: 에너지) 상품을 옮기기

**막힌 수강생 대응**

- "콘솔 → Network 탭 → 백엔드 터미널" 순서로 확인하는 습관을 첫날부터 만듭니다. 질문하기 전에 에러 문구를 먼저 복사해 오게 합니다.
- 10분 이상 막히면 다음 단계 스냅샷으로 합류하고, 쉬는 시간에 차이(diff)를 같이 봅니다.
- 빨리 끝낸 수강생에게는 변형 과제를 주거나 옆자리 수강생을 돕게 합니다.

**평가**

- 단계별: 확인 포인트 통과 여부만 봅니다 (통과/미통과).
- 최종 과제: 7단계와 같은 흐름으로 새 기능 하나를 풀스택으로 추가합니다. 예: 상품 상세 화면(`GET /products/{id}` + 상세 페이지), 가격대 필터.

## 트러블슈팅 모음

실습 중 가장 자주 나오는 문제는 "백엔드가 꺼져 있어서 생기는 502"입니다. 아래 표를 교실에 띄워 두면 수강생이 스스로 찾아볼 수 있습니다.

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| "상품 검색 실패 (HTTP 502)" | 백엔드(8001)가 꺼져 있어 Vite 프록시가 요청을 넘길 곳이 없음 | 백엔드 터미널에서 서버를 다시 실행. PC를 재시작하거나 터미널을 닫으면 꺼짐 |
| "HTTP 500" | 백엔드 코드 또는 SQL 오류 | 백엔드 터미널의 에러 로그 확인 |
| "HTTP 422" | 파라미터 값이 규칙에 맞지 않음 (예: `category_id=0`, 없는 정렬값) | 응답의 `detail`에서 어느 값이 틀렸는지 확인 |
| 백엔드를 고쳤는데 반영이 안 됨 | `--reload` 없이 실행함 | 서버를 끄고 `--reload`를 붙여 다시 실행 |
| 검색 결과가 비거나 예상과 다름 | 운영 DB(`vmshop`)로 서버를 띄움 | `$env:DB_NAME='test_vmshop'`을 지정했는지 확인 |
| 이미지가 깨짐 | DB 경로(`/products/images/...`)와 프론트 `public/images` 경로가 다름 | `toImageUrl()`로 파일 이름만 꺼내 변환. 파일이 없으면 기본 아이콘 |
| 콘솔에 "unique key prop" 경고 | `map()`으로 그린 요소에 `key`가 없음 | `key={product.id}`처럼 바뀌지 않는 값을 쓰고 배열 번호는 피함 |
| "Too many re-renders" | `onClick={함수()}`처럼 렌더링 중에 상태를 바꿈 | `onClick={() => 함수()}`로 감싸기 |
| 요청이 끝없이 반복됨 | `useEffect` 의존성 배열에 매번 새로 만들어지는 객체를 넣음 | 문자열 키(`JSON.stringify`)나 원시값만 넣기 |
| 검색어를 빠르게 바꾸면 예전 결과가 보임 | 늦게 도착한 예전 응답이 새 결과를 덮어씀 | 정리 함수에서 `ignore = true`로 설정해 예전 응답 버리기 |
| 주소는 바뀌었는데 화면은 그대로 | `pushState`만 부르고 상태를 바꾸지 않음 | `navigate()`에서 두 가지를 함께 처리 |
| Git Bash curl로 한글 검색하면 0건 | 한글 검색어 인코딩이 깨짐 | 브라우저나 `/docs`에서 테스트 |
